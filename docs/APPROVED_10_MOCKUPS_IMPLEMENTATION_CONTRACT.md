## Integration roadmap — controlled, bounded PRs

1. **S0 — Freeze contract and source baseline (this document):** product Bible and Roadmap pointers, identify already-implemented behavior vs remaining deltas. No APK.
2. **S1 — Global Search:** implement single-character title-only rules, visible match evidence, newest/oldest/A–Z sorting, localized UI and unit/widget regressions; existing search routes, type/archived/diary search remain intact.
3. **S2 — Inbox taxonomy:** reusable existing tag model; durable catalog/renaming with atomic/rollback-safe multi-entity changes across active + archived Inbox, add/filter/manage UI, account isolation and sync tests. Avoid a second personal search or diary database.
4. **S3 — Shared invitations and Messages:** reuse existing server-validated 24h invites; QR generation/scan and visual selection; owner permissions, expiry, 2+ joiners, old-code revocation, no external secret processing; preserve shared encryption and existing code paths.
5. **S4 — Remaining visual-only integration:** reconcile Oggi/nav, Calendario, Ricordi, Altro/Impostazioni and Capture micro-bounce against actual current UI5/v1.08 code. Apply *deltas only*. Cassaforte is explicitly unchanged. Preserve 5-language localization, accessibility, responsive screens and navigation reachability.
6. **S5 — QA and release boundary:** exact-head analyze/test/Web/AppLab **Source Gate** on integrated PRs; no automatic PR-triggered APK. Manual stable-signed ARM64 APK at versionCode **strictly greater than 111** and same package/signing; user performs physical in-place update with user records untouched and explicit **Inbox tag create → rename → category filter → restart → verify**, QR scans on separate devices, reduced motion, navigation, search, privacy, theme and Vault smoke. Stop release if required evidence is unavailable.

## Acceptance and evidence

- Source implementation, merged source, artifact build, phone smoke, physical regression and Store readiness are separate evidence labels.
- All notes/photo/voice/sketch, messages, invitations, stored IDs, local/cloud queues, encryption keys, archive/Trash and backups retain canonical ownership.
- New visible examples belong to mock-ups only. Production must use authentic user data or true empty states; never seed fake memories, diary content or credentials.
- No new dependencies unless reviewed for APK footprint, offline support and data/privacy safety.
- Every code PR must cite scope, affected files, test evidence and *explicitly unverified* native or two-device steps.
